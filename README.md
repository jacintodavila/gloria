## DIRECTORIES
The Gloria source directory consists of the following files:

* gloria.pl: The main programs and some suggestions to adapt the agent.
* implica.pl: The part of the reasoning engine that deals with implications.
* rplan.pl: The main part of the reasoning engine.
* equiva.pl: Predicates to process equivalent formulai.
* rewrite.pl: Predicates to cater for equalities and inequalities.
* auxilia.pl: Supporting predicates. 
* gcompile.pl: The compiler from openlog and actilog into prolog (.kb).
* tokenizer.pl: A supporting program for gcompile.pl.
* gtester.pl: A simple text-based interface to run and test agents.
* COPYING: The GPL licence covering Gloria.
* VERSION: Current version of Gloria.
* README.md: This file.

## BUILDING Gloria
It couldn't be easier. Gloria is a Prolog program without even modules. Just include (e.g., `:- [gloria].`) the file from within your application and you will have access to all its predicates. 

## USING Gloria Tools

### Compiling Agents (`gcompile.pl`)
To compile a agent-based system description (`.g` file) into individual agent files (`.kb` and `.main`):

1. Start your Prolog interpreter.
2. Load the compiler: `?- ['gcompile'].`
3. Process your `.g` file: `?- process_g_file('path/to/your_agent.g').`

### Testing Agents (`gtester.pl`)
To run an interactive text-based simulation of an agent:

1. Navigate to the folder containing your agent's `.main` and `.kb` files.
2. Start your Prolog interpreter.
3. Load the tester: `?- ['../../gtester'].`
4. Start the simulation: `?- start_test('AgentName', agent_module_name).`

The tester will prompt you for inputs at each time step and display the actions generated by the agent.

## WEB INTERFACE
Gloria includes a modern React-based web interface.

### Prerequisites
- SWI-Prolog
- Node.js and npm

### Building the Interface
1. Build the React client:
   ```bash
   cd web/client
   npm install
   npm run build
   ```

### Starting the Server
1. Run the Prolog server:
   ```bash
   cd web/server
   swipl -s server.pl -g start_server
   ```
2. Access the interface at `http://localhost:8080`.
